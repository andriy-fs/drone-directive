# Ракетная установка базы + дрон-наблюдатель у ИИ — implementation plan

**Не реализовано.** План согласован, код не написан. Ссылки на строки соответствуют дереву
на момент составления (незакоммиченная работа по `DefendBase`/`GroupAttack` уже в нём).

## Context

Две связанные проблемы баланса, обе про разведку и про то, что база ничего не может.

**1. База беспомощна.** `spawnBase` (`client/src/engine/ecs/factory.ts:10-33`) даёт зданию
только `hp` (600), `sightRange` (260), `footprint` и `production` — ни `weapon`, ни
`targetId`. А `combatSystem` (`client/src/engine/systems/combat.ts:29`) стреляет строго из
запроса `world.with('robot','position','weapon')`. Итог: база видит на 260 px и не может
ответить вообще ничему, включая дрон-наблюдателя, который висит над ней бесплатно и
безнаказанно. Единственное средство против дрона в игре — `missiles` (`canHitAir: true`,
`gameConfig.ts:138-148`), и оно есть только у роботов.

**2. У ИИ нет глаз.** `gameScene.ts:75-79` явно пропускает бот-стороны при спавне дрона, а
`droneRespawnSystem` фильтрует по `Controller.Human` (`droneRespawn.ts:24`). При этом
`visionSystem` уже честно считает `intel` **для каждой** стороны роутера, и тактический слой
бота не жульничает: `juiciestCluster` и все директивы ходят через `knownEnemyRobots`/
`knownEnemyBases` (`targeting.ts:59-69`). Жульничество у бота осталось только
стратегическое — `nearbyEnemyCount`/`forcePosture` считают живых роботов по всей карте
(`ai.ts:283-304, 390-400`). То есть у игрока есть летающий глаз со скоростью 280 px/с и
обзором 220 px, а у бота — только наземные юниты и база.

**Результат:** база перестаёт быть мишенью для бесплатного облёта, а у бота появляется
собственный глаз — и вместе с ним появляется контр-игра: этот глаз можно сбить
(60 hp, без регенерации, 30 с респавна).

## Принятые решения

- **Одна ракетная установка, никакой пушки.** Ровно `gameConfig.robots.weapons.missiles`
  (range 170, damage 22, cooldown 1.6, `canHitAir`). Пушка сверху сделала бы штурм базы
  нереальным — прямая просьба этого избежать.
- **Приоритет — воздух.** Установка сначала выбирает замеченный вражеский дрон, и только
  если его нет в радиусе — ближайшего замеченного робота. Смысл установки именно в том,
  чтобы дрон перестал висеть над базой бесплатно. **Осознанный размен:** пока в радиусе
  висит дрон, камикадзе проходит легче — это цена приоритета, а не баг.
- **Дальность меряется от центра footprint, ровно 170.** Как у робота с ракетами, который
  тоже целится в центр базы. Дуэль «база против ракетного робота» остаётся ровной; база не
  выигрывает перестрелку автоматически.
- **Цели — только `known*`, без всеведения.** Установка ходит через
  `knownEnemyDrones`/`knownEnemyRobots`. Обзор базы (260) больше дальности (170), так что в
  норме всё, до чего она достаёт, она и видит. **Эмерджентное следствие, которое оставляем:**
  вражеский `ew` рядом режет обзор базы вдвое (260 → 130 < 170) и реально ослепляет
  установку на краю радиуса — это уже работающая контр-игра, отдельного кода не требует.
- **Симметрия.** Установку получают базы **всех** сторон, включая ботов. Игрок теряет
  бесплатный облёт чужой базы ровно так же, как бот.
- **Дрон у ИИ — тот же самый дрон.** Стек уже owner-generic: `droneSystem` водит все дроны
  из `ctx.droneControl[owner]` (`drone.ts:32`), `visionSystem` уже считает дроны скаутами
  каждой стороны (`vision.ts:42`), `airTarget` уже разрешает ракетным роботам бить чужие
  дроны (`task.ts:128-138`). Нужны две снятые заглушки и «пилот», пишущий `DroneControl`.
- **Ограничения бота: не садится на роботов и не стреляет.** Обеспечивается структурно —
  пилот никогда не выставляет `possessPulse`/`firePulse` в `true`. Побочный эффект в нашу
  пользу: `isTargetableDrone` (`targeting.ts:45`) исключает дрон, сидящий на роботе, — бот
  никогда не садится, значит его дрон **всегда** сбиваем. Это и есть плата за преимущество.
- **Один дрон на всех сложностях, с теми же цифрами** (220 px обзор, 60 hp, 30 с респавна).
  Сложность в игре и так меняет ровно одно — стартовый состав (`gameConfig.ts:276-281`);
  вводить вторую ось не нужно.
- **Ничего не уходит на провод.** Бот считается внутри детерминированного пайплайна на
  каждом пире (`gameScene.ts:90-93`), позиция дрона попадает в `worldHash` сама (хеш обходит
  все сущности). `protocol`/`net`/`server` не трогаем, `PROTOCOL_VERSION` не бампим.

## Фаза 1.3 — выбор цели (`systems/task.ts`)

`task.ts` — единственное место, где выставляется `targetId`; `combat.ts` его только
потребляет. Установка не ломает это правило: цель ей выбирает тот же резолвер, просто
отдельным проходом (у базы нет ни `script`, ни `movement`, поэтому в основной цикл она не
попадает).

В конце `taskSystem` (69-81), **после** цикла по роботам:

```ts
for (const b of ctx.world.with('base', 'position', 'weapon')) {
  if ((b.hp ?? 0) <= 0) continue;
  b.targetId = baseTurretTarget(ctx, b);
  const t = b.targetId ? findById(ctx, b.targetId) : undefined;
  if (t?.position) b.heading = Math.atan2(t.position.y - b.position!.y, t.position.x - b.position!.x);
}
```

`heading` нужен только рендеру (ствол доворачивается на цель); в `worldHash` он не входит —
как и у роботов, он производный.

Новая функция рядом с `airTarget` (128-138), которая её и зеркалит:

```ts
/**
 * Цель встроенной установки базы. Воздух в приоритете: установка существует
 * именно потому, что база не могла тронуть дрон-наблюдателя — иначе достаточно
 * подставить один наземный робот, и дрон снова висит бесплатно. Цена решения:
 * пока в радиусе есть дрон, камикадзе идёт к стене без помех.
 *
 * Только `known*` — база не всеведуща; вражеский `ew` рядом режет её обзор
 * вдвое (260 → 130) и реально ослепляет установку на краю дальности.
 */
function baseTurretTarget(ctx: GameContext, base: Entity): string | undefined {
  const w = base.weapon;
  if (!w || !canEngage(w)) return undefined;
  const pos = base.position!;
  const inReach = (e: Entity): boolean =>
    distance(pos.x, pos.y, e.position!.x, e.position!.y) <= w.range &&
    hasLineOfSight(ctx.sightBlockers, pos, e.position!);

  if (w.canHitAir) {
    const drone = nearest(pos, knownEnemyDrones(ctx, base.owner!).filter(inReach));
    if (drone) return drone.id;
  }
  return nearest(pos, knownEnemyRobots(ctx, base.owner!).filter(inReach))?.id;
}
```

`canEngage` импортируется из `combat.ts` (уже экспортирован, `combat.ts:64`), `findById`/
`nearest`/`knownEnemy*` — из `targeting.ts`, всё уже используется в этом файле.

Порядок пайплайна не меняется: `vision → task → … → combat`, так что установка стреляет по
свежему intel того же тика.

## Фаза 1.4 — выстрел (`systems/combat.ts`)

## Фаза 2.2 — пилот (`client/src/engine/systems/aiDrone.ts`, новый)

Отдельный модуль, а не ещё сотня строк в `ai.ts` — прецедент `systems/status.ts`. Экспорт
один: `pilotDrone(ctx, owner)`. Вызывается из `runBot` (`ai.ts:57-72`) последним шагом, после
`sweepIdle`. `aiSystem` идёт **до** `droneSystem` в том же тике (`gameScene.ts:94-100`), так
что записанный `DroneControl` потребляется сразу — никакого нового места в пайплайне.

```ts
export function pilotDrone(ctx: GameContext, owner: Owner, state: AiState): void {
  const drone = ctx.world.with('drone','position').entities.find(d => d.owner === owner && (d.hp ?? 0) > 0);
  const control = ctx.droneControl[owner];
  // Ограничения бота — структурные: пульсы не выставляются никогда.
  control.possessPulse = false;
  control.firePulse = false;
  if (!drone) { control.dir = { x: 0, y: 0 }; state.droneWaypoint = undefined; return; }

  const goal = breakOff(ctx, owner, drone) ?? escortGoal(ctx, owner, drone) ?? sweepGoal(ctx, owner, drone, state);
  control.dir = goal ? unitToward(drone.position!, goal) : { x: 0, y: 0 };
}
```

Три правила, в порядке приоритета:

1. **`breakOff` — разрыв контакта.** Если живой вражеский робот с `weapon.canHitAir` или
   живая вражеская база находятся ближе `ai.droneDangerRange`, вернуть точку **от** ближайшей
   такой угрозы (позиция дрона + нормаль от угрозы × дальность). Скорость дрона 280 против
   дальности ракет 170 — уйти он успевает, если начинает вовремя. Отдельно: пока
   `hp / maxHp <= ai.droneCautiousHp`, дрон вообще не уходит дальше `ai.dronePicketRadius`
   от своей базы. Дроны **не регенерируют** (`regen.ts:19-21` — исключены по построению),
   поэтому битый дрон — это невосполнимый ресурс: разумнее держать его как раннее
   предупреждение у базы, чем разменять на один заход.
2. **`escortGoal` — идти впереди своей группы.** Если есть свои живые роботы с
   `isAdvancing(r)` (экспорт из `task.ts:49`), вернуть центроид группы, сдвинутый **от**
   своей базы на `ai.droneScoutLead` px — зеркало `overwatchOutcome` (`task.ts:480-500`),
   только вперёд, а не назад. Хелпер `centroidOf` (`task.ts:509`) сейчас приватный — сделать
   экспортируемым и переиспользовать, а не копировать.
3. **`sweepGoal` — свипы.** Держать `state.droneWaypoint`; перевыбирать, когда дистанция до
   него меньше `ai.droneWaypointRadius` или его нет. Выбор точки:
   - если `knownEnemyBases(ctx, owner)` непуст — с вероятностью 1/2 точка на окружности
     вокруг известной вражеской базы радиусом чуть больше её дальности
     (`bases.weapon`.range + запас), иначе случайная точка карты;
   - если ничего не известно — случайная точка карты, как `searchOutcome` для роботов.

   **Детерминизм:** `ctx.rng` дёргается **только** в момент перевыбора точки (тот же приём,
   что в `roamOutcome`, `task.ts:389`), боты идут в порядке роутера — поток rng совпадает у
   пиров. `Math.random` в системах запрещён.

Клампить цель мировыми границами не нужно — `freeFly` (`drone.ts:56-57`) уже клампит позицию.

**`client/src/engine/game/context.ts`** — в `AiState` (51-57) добавить:

```ts
/** Пилот дрона: текущая точка свипа; перевыбирается по прибытии (см. systems/aiDrone.ts). */
droneWaypoint?: Vec2;
```
и оставить её `undefined` в `emptyAiState()` (81-88).

## Проверка

Текущее дерево уже содержит незакоммиченную работу по `DefendBase`/`GroupAttack` — эти
изменения ложатся поверх неё; гонять полный набор до и после.

1. `npm run build` — чисто.
2. `npm test` — `net`, `chat`, движок; новые тесты зелёные.
3. `npm run lint` — чисто.
4. `npm run type-check` — трогаем `types`? нет; но прогнать обязательно, если правки заедут
   в `types/`/`protocol/` (по плану не должны — это и есть проверка, что не заехали).
5. `npm run dev:relay` + `npm run e2e -w server` — рукопожатие не менялось, но онлайн-матч
   должен идти без desync-предупреждений в консоли (дрон бота — в `worldHash` через позицию).

**Живьём** (`npm run dev`):

- Подлететь дроном к вражеской базе: на 170 px от её центра база доворачивает ствол и
  открывает огонь ракетами (звук ракеты). Три попадания (22 × 3 = 66 > 60 hp) — дрон сбит,
  панель дрона уходит в 30-секундный отсчёт.
- Отвести дрон за 170 px — огонь прекращается; обзор дрона (220) позволяет продолжать
  наблюдение с безопасной дистанции. Это и есть новая рабочая дистанция разведки.
- Подвести робота в радиус базы вместе с дроном — база стреляет **по дрону** (приоритет
  воздуха), робот получает свободный подход. Ожидаемо.
- Подвести `ew`-робота вплотную к вражеской базе — установка перестаёт доставать до целей
  на краю радиуса (обзор базы 130 < дальность 170).
- Камикадзе (tracks/bomb, 120 hp) доезжает от 170 px до стены под огнём и детонирует —
  штурм базы остаётся реальным.
- У бота виден собственный дрон (в цвете противника, не синий), но **только** когда он
  засечён; он летит впереди наступающей волны бота, не садится на роботов и не стреляет.
- Ракетный робот игрока сам открывает по нему огонь, когда тот заходит в 170 px
  (`airTarget`, преследования нет); база игрока — тоже.
- Сбитый дрон бота возвращается через 30 с; битый дрон бота (<34 % hp) перестаёт летать
  вперёд и держится у своей базы.
- Онлайн 1v1 с ботом третьей стороной: в консоли нет предупреждений о рассинхроне.
