# Переход на семплы через @pixi/sound — implementation plan

Design record, agreed but **not yet implemented**. Nothing in the repository has been changed for it.

## Context

Весь звук в игре синтезируется на лету в `client/src/pixi/audio/sfx.ts`: примитивы `tone`/`noise`/`metal`, самодельная мастер-шина (`GainNode` → `DynamicsCompressorNode` → `destination`) и посылка на `ConvolverNode` с импульсом, сгенерированным кодом.

Синтез довели до приемлемого уровня (атаки, длительности, резонансные фильтры, негармоничные партиалы), но потолок этого подхода достигнут. Решено перейти на семплы, воспроизводимые через `@pixi/sound` 6.0.1 (peer `pixi.js ^8`, совместим с текущим 8.19; 34 КБ min / 9.4 КБ gzip).

Побочно это **снижает** нагрузку на CPU: `robotSelected(Tracks)` сейчас строит ~40 узлов графа, из них 12 осцилляторов, считаемых посэмплово; семпл — это один `AudioBufferSourceNode`. Плюс удаляется `ConvolverNode` — самый дорогой из добавленных узлов.

**Материал уже есть.** В `client/public/sounds/` лежат 235 файлов `.ogg` (7.6 МБ, пока не закоммичены) в трёх папках — это паки Kenney: `digital` (62), `interface` (100), `sci-fi` (73). Все **CC0**, атрибуция не требуется, файл `CREDITS.md` не нужен. Конкретные реплики выбраны — см. раздел «Выбранные звуки».

### Принятые решения

1. **Полная замена сразу.** `tone`/`noise`/`metal`/`bus`/`roomImpulse`/`whiteNoise`/`chassisVoice` удаляются, `sfx.ts` становится тонкой обёрткой над `sound.play()`.
2. **13 реплик**: `shot-cannon`, `shot-missile`, `explosion`, `chat-message`, **`chat-send`**, `select-base`, `select-tracks`, `select-wheels`, `select-legs`, `select-group`, `unit-ready`, **`button-click`**, **`modal-open`**.
3. **Ползунок громкости + сохранение** громкости и mute в localStorage (сегодня mute сбрасывается при каждой перезагрузке).

### Что не меняется

Публичный фасад `sfx` сохраняет сигнатуры всех 11 существующих членов, поэтому **все 8 текущих мест вызова не трогаются**: `GameApp.wireBus` (`client/src/pixi/GameApp.ts:236-256`), `client/src/pixi/audio/selectionAudio.ts`, `client/src/chat/chatBridge.ts`, `client/src/ui/hud/SoundToggle.tsx`, `MainMenu.tsx`, `OnlineLobby.tsx`. `client/src/pixi/audio/selectionSound.ts` и его тест не затрагиваются вообще.

Добавляются **три новых члена** (`buttonClick()`, `modalOpen()`, `chatSend()`) и три новых места вызова — два в `ui/common/`, одно в `chat/chatBridge.ts` — см. Фазу 3.

## Фаза 1 — подготовка файлов

### 1.1 Библиотеку-источник убрать из `public/` — иначе 7.6 МБ уедут в прод

`client/public/` копируется Vite в `dist/` **целиком** и уходит одним артефактом на GitHub Pages. Сейчас там 5.1 МБ картинок; 235 неиспользуемых `.ogg` добавят к этому ещё 7.6 МБ. Файлы пока не закоммичены, поэтому решать надо **до** первого коммита.

Перенести библиотеку в `client/public/sounds/.tmp/` (шаблон `.tmp` в `.gitignore` не заякорен, поэтому такая папка игнорируется автоматически — так же сделано для исходников спрайтов в `client/public/.tmp/`), либо вообще за пределы репозитория. В `dist` должны попасть только 13 выбранных реплик.

### 1.2 Конвертация в `client/public/sfx/`

**Обработки почти не требуется** — файлы Kenney уже отвечают требованиям, которые в исходной версии этого плана предполагалось выполнять руками (проверено `ffprobe`/`volumedetect` по всем 13 отобранным):

- пик у всех −0.9…−1.4 dBFS, то есть уже нормализованы. Два исключения, оба лечатся числом в таблице `volume`, а не перенормировкой файла: `laserSmall_000` на −5.7 dBFS (тише ряда) и `pluck_001` на −0.0 dBFS (на полной шкале);
- тишины в начале нет ни у одного — транзиент на нулевом сэмпле;
- все 44.1 кГц; часть моно, часть стерео.

**Формат на выходе — `.wav`, моно.** Исходники `.ogg`, и Ogg Vorbis, в отличие от MP3/AAC, не несёт priming delay кодировщика, так что по этой линии он был бы безопасен. Решающий довод другой: **поддержка Ogg Vorbis в `decodeAudioData` у Safari исторически отсутствует и остаётся ненадёжной**, а тихий отказ всего звука на целом браузерном семействе — слишком дорогая цена за экономию 250 КБ. Конверсия `.ogg` → `.wav` это декодирование, а не перекодирование, поэтому качество не теряется.

Замеренный итог: **~480 КБ** на 13 файлов против 5.1 МБ уже отгружаемых PNG (один тайл земли — 1.67 МБ).

```
# из client/public/sounds/, для каждой пары «источник:имя» из таблицы ниже
ffmpeg -v error -y -i "<источник>.ogg" -ac 1 -ar 44100 -sample_fmt s16 "../sfx/<имя>.wav"
```

Стерео сводится в моно намеренно: панорамирования в игре нет, а `WebAudioContext` всё равно суммирует в стереовыход.

**Никогда не добавлять query-строку к URL звука**: `@pixi/sound` определяет формат разбором расширения из URL.

## Фаза 2 — подмена движка

### 2.1 `client/src/config/sounds.ts` (новый)

Зеркалит `client/src/config/sprites.ts`:

```ts
const PUBLIC_BASE = import.meta.env.BASE_URL;

export interface SoundDef {
  /** `null` = файла ещё нет; реплика молчит, сборка зелёная. */
  src: string | null;
  /** Относительный баланс микса; см. таблицу ниже. */
  volume: number;
}
export type SoundName = 'shot-cannon' | 'shot-missile' | /* … */ 'modal-open';
export const soundDefs: Record<SoundName, SoundDef> = { /* … */ };
export function soundSources(): { name: SoundName; src: string }[];
```

**Два обязательных ограничения:**

- URL строятся **только** через `` `${PUBLIC_BASE}sfx/x.wav` ``. В продакшене `base: './'` (`client/vite.config.ts`, деплой на GitHub Pages), поэтому абсолютный `/sfx/x.wav` даст 404. `PUBLIC_BASE` — единственная точка, ровно как в `sprites.ts`.
- Файл **не импортирует `@pixi/sound`**. `config/` попадает в граф зависимостей `ui/`; `sprites.ts` не импортирует pixi, и здесь должно быть так же. `SoundSourceMap` собирается в `pixi/`.

Баланс (воспроизводит текущий микс синтеза; `explosion` 0.18 = 1.0). Все файлы на одном пике, поэтому эти числа задают относительную громкость напрямую:

| реплика | volume | реплика | volume |
|---|---|---|---|
| `explosion` | 1.0 | `select-group` | 0.30 |
| `shot-missile` | 0.50 | `modal-open` | 0.25 |
| `select-base` | 0.42 | `chat-message` | 0.19 |
| `select-tracks` / `-wheels` / `-legs` | 0.40 | `unit-ready` | 0.17 |
| `shot-cannon` | **0.38** | `button-click` | 0.15 |
| | | `chat-send` | 0.13 |

`shot-cannon` выбивается из ряда намеренно: исходник на 4.8 дБ тише остальных (−5.7 против −1 dBFS), 0.22 / 0.58 ≈ 0.38. Если файл заменят на другой, число вернуть к 0.22.

### 2.2 `client/src/pixi/assets.ts` — загрузка

Добавить `loadSoundAssets()` рядом с `loadGameAssets()`, тем же стилем: один `try/catch`, ошибка логируется и глотается, приложение работает без звука.

**Грузить через `Assets.load`, а НЕ через `sound.add(map, { preload: true })`.** Причина: `WebAudioMedia._loadUrl` — `async` без `try/catch`, и `load()` вызывается без `.catch`, поэтому 404 на любом файле даёт необработанный rejection, а колбэк `loaded` его не ловит (он видит только ошибки декодирования). Импорт `@pixi/sound` сам регистрирует парсер (`extensions.add(soundAsset)` на уровне модуля), поэтому:

```ts
const map = await Assets.load<Sound>(soundSources().map((s) => s.src)); // reject → наш catch
for (const { name, src } of soundSources()) sound.add(name, map[src]);
```

**Вызывать без `await`** из `GameApp.init()`, причём **до** `await this.app.init(...)`, чтобы десяток мелких запросов шёл параллельно с инициализацией рендерера и загрузкой 5.1 МБ спрайтов, а не в очереди за ними. `GameCanvas` смонтирован на всю сессию, так что `init()` — это загрузка приложения, а не старт матча.

### 2.3 `client/src/pixi/audio/sfx.ts` — переписать

Удалить: `tone`, `noise`, `metal`, `bus`, `roomImpulse`, `whiteNoise`, `chassisVoice`, `METAL_PARTIALS`, интерфейсы `Voice` / `NoiseVoice`, модульное состояние `ctx`, `muted`, `master`, `room`, `noiseBuf`.

**Перед удалением перенести докблоки в `.docs/sfx/README.md`** (Фаза 5). Тексты вида «два дискретных шага сервоприводов, опознаётся по ритму», «пресс идёт вниз, звенит плита, разгоняется конвейер», «негармоничные партиалы отличают его от чистых синусов чата», вместе с конкретными частотами и длительностями — это **единственная существующая спецификация того, чем эти звуки должны быть**, и она понадобится при любой будущей замене файлов. Их потеря — главный риск всей миграции.

Ключевые моменты реализации:

- **Гард на воспроизведение — состояние загрузки, а не `exists`.** `sound.exists(alias)` истинно сразу после `sound.add`, до загрузки байтов, а `Sound.play()` в этом состоянии **ставит вызов в очередь и проигрывает после декодирования** — то есть залп протухших взрывов через несколько секунд после события. Держать модульный `ready: Set<SoundName>`, заполняемый загрузчиком, либо проверять `sound.find(name)?.isLoaded`. (`find` при промахе делает `console.assert` и возвращает `undefined` — не бросает, но даст `TypeError` на `.play`.)
- **`autoPause` выключить.** `WebAudioContext.onBlur` при `autoPause = true` (значение по умолчанию) **суспендит весь AudioContext при потере фокуса окна**. Сегодня синтез при alt-tab продолжает звучать; после миграции это убьёт уведомление чата — единственную реплику, чья задача как раз дотянуться до игрока, который не смотрит в окно. Требуется `instanceof WebAudioContext` (в `IMediaContext` поля нет) и `ctx.autoPause = false`.
- **`groupSelected(chassis, count)`**: `play('select-group', { speed: count >= 8 ? 0.85 : 1 })` — изменение скорости понижает тон и удлиняет звук (0.53 → ~0.62 с), ровно то, что старый код делал вручную. **Плюс** первая по `orderChassis` реплика шасси на пониженной громкости через `setTimeout(…, 70)`. Задержка обязательна: два `sound.play` в одном синхронном такте стартуют в одном 128-сэмпловом кванте, то есть строго на одном сэмпле — это когерентное сложение, тот самый «один громкий щелчок», от которого защищает порог в `unitReady`. Джиттер таймера ±10 мс на сдвиге 70 мс неслышен. Это же сохраняет параметр `chassis` использованным (иначе `noUnusedParameters` валит сборку) и оставляет `selectionAudio.ts` без единой правки.
- **`explosion()`**: добавить джиттер `speed: 0.94 + Math.random() * 0.12` и коалесцирующий порог 120 мс. `entityDestroyed` при массовой жатве приходит синхронно пачкой, а одинаковые буферы, стартующие в один сэмпл, складываются когерентно — раньше от этого спасал `src.start(t, Math.random() * 1.5)` со случайным офсетом чтения, которого больше нет. `singleInstance` здесь **не** годится: он обрывает предыдущий экземпляр, и залп превратится в заикание.
- **`unitReady()`**: порог остаётся, но переводится на `performance.now()` — `AudioContext.currentTime` не идёт, пока контекст suspended, поэтому текущий порог до первого жеста вырожден. При переводе `0.12` → `120` и `lastUnitReadyAt = -1` → `-Infinity`, иначе первые ~119 мс после загрузки страницы пип глотается (в `selectionAudio.ts` уже `-Infinity`).
- **`resume()`** → `void sound.context.audioContext.resume()`. Все 4 места вызова оставить: авто-разблокировка у библиотеки есть, но она вешает слушатели `mousedown`/`touchstart` только если контекст был suspended на момент конструирования, и клавиатурный старт ею не покрыт.
- **`setMuted`/`isMuted`** → `sound.muteAll()` / `sound.unmuteAll()` / `sound.context.muted`. Читается обратно корректно (`muteAll` = `_context.muted = true; refresh()`). **Никогда не писать `sound.context.muted = x` напрямую** — без `refresh()` значение не применяется.
- Компрессор **не теряется**: у `WebAudioContext` цепочка `analyser > compressor > destination` с дефолтами браузера (−24 / 30 / 12 / 0.25), агрессивнее нашей ручной (−18 / 20 / 6 / 0.2). Защита от перегрузки улучшится, на залпах возможен чуть более заметный pumping.

## Фаза 3 — интерфейсные звуки и чат (новое)

Три новые реплики и, впервые, звук, который вызывается из React-слоя. Прецедент уже есть: `ui/` импортирует `pixi/audio/sfx` в `SoundToggle.tsx`, `MainMenu.tsx` и `OnlineLobby.tsx`, так что границы слоёв это не нарушает.

### 3.1 Кнопка и модальное окно

Обе точки входа — единственные и полные, проверено:

- **`sfx.buttonClick()` → `client/src/ui/common/Button.tsx`.** Тонкая обёртка над Headless UI, через неё проходят **все** кнопки приложения (14 файлов-потребителей, ни одного сырого `<button>` в кодовой базе). Обернуть `onClick`: сначала звук, затем прокинуть исходный обработчик. Не забыть про `disabled` — на заблокированной кнопке звука быть не должно.
- **`sfx.modalOpen()` → `client/src/ui/common/Dialog.tsx`.** Тоже полная обёртка, её используют 6 модалок (`GameOverModal`, `ControlsModal`, `UnitsGuideModal`, `BaseSetupModal`, `BuildRobotModal`, `OnlineLobby`). Состояние `open` приходит пропсом от вызывающего, поэтому звук вешается на переход `false → true` через `useEffect` с отслеживанием предыдущего значения — иначе он будет играть на каждом ререндере открытой модалки.

Оба звука тихие (0.15 и 0.25 в таблице): они срабатывают чаще любых других и обязаны быть тем, что перестаёшь замечать.

**Не входит в объём:** звук закрытия модалки. Если он понадобится, парой к `interface/open_002.ogg` идёт `interface/close_002.ogg` (0.314) — это одна строка в таблице и одна ветка в том же `useEffect`.

Отдельно учесть: `SoundToggle` построен на `Switch`, а не на `Button`, поэтому переключатель звука кликать не будет. Это скорее к лучшему — щелчок в момент выключения звука сбивает с толку.

### 3.2 Чат

Сегодня у чата ровно один звук — `sfx.chatMessage()` на входящее сообщение (`client/src/chat/chatBridge.ts:51`), и он уже переведён на файл (`chat-message`). Слышно, когда сообщение **приходит**, но не когда своё **уходит** — вторая половина пары добавляется здесь.

- **`sfx.chatSend()` → `sendChat(text)` в `chatBridge.ts:163`, только при успешной отправке.** Ставить именно в мост, а не в панель: отправка идёт двумя путями — кнопкой (`ChatPanel.tsx:135`) и по Enter (`onSubmit`, `ChatPanel.tsx:115`), — и общая точка у них одна.
- Звук должен быть **тише и тембрально противоположен** `chat-message`: пара «ушло / пришло» читается только если реплики не путаются между собой.

**Столкновение, которое надо разрулить.** Кнопка отправки — это `common/Button`, поэтому после 3.1 она уже играет `button-click`. Если `chatSend()` сработает в том же синхронном такте, два буфера стартуют в одном 128-сэмпловом кванте и сложатся когерентно — тот же «громкий щелчок», от которого мы уходим в `groupSelected` и `explosion`. Решение: добавить `Button` необязательный проп отказа от звука (`silent`) и выставить его на кнопке отправки чата. Путь через Enter кнопку не задействует, так что после этого оба пути звучат одинаково — ровно одним `chat-send`.

**Что звука не требует:** кнопка-лончер чата (`ChatPanel.tsx:35`) — это тоже `Button`, она получает `button-click` автоматически, отдельная реплика открытия панели не нужна.

**Не входит в объём:** появление и уход оппонента в чате. Хук есть — `onPresence` (`chatBridge.ts:55`), но он вызывается и с текущим значением, поэтому потребует сравнения с предыдущим, иначе звук будет повторяться. Кандидат на файл — `interface/bong_001.ogg` (0.123). В онлайне это полезный сигнал; включать по отдельному решению.

## Фаза 4 — громкость и mute

- Ключи `dd:sfxMuted` / `dd:sfxVolume` через `client/src/utils/storage.ts` — всё хранилище идёт только через него, прямых обращений к `localStorage` в проекте нет. Конвенция чтения как у `dd:chatSound`: отсутствие значения = дефолт (не muted, громкость 1). Значение применяется при инициализации модуля `sfx.ts`, поэтому `useState(sfx.isMuted())` в тоглле остаётся верным.
- `sfx.setVolume(v)` / `sfx.getVolume()` → `sound.volumeAll` (0..1).
- Слайдера в `client/src/ui/common/` **нет** (там `Bar`, `Button`, `Dialog`, `icons`, `Picker`, `Switch`), и `<input type="range">` в проекте не встречается ни разу. Нужен новый `common/Slider.tsx` + стили в `client/src/ui/App.css`.
- `client/src/ui/hud/SoundToggle.tsx` получает слайдер рядом с динамиком (рендерится из `App.tsx:76`, блок `hud__controls`).
- **i18n обязателен, иначе `tsc -b` падает**: `Dict` — явный интерфейс в `client/src/i18n/locales/en.ts` (секция `aria` на строке 164), а `dictionaries: Record<Locale, Dict>` в `client/src/i18n/index.ts:10` требует, чтобы новый ключ `aria.volume` появился **во всех четырёх** локалях: `en`, `ru`, `uk`, `pl`.

### Ограничения этого набора, принятые сознательно

- **Палитра — синтезированный sci-fi/UI, а не индустриальная документалистика.** Настоящего лязга гусениц и гула заводского цеха в паках Kenney нет; `impactMetal` и `doorOpen` — ближайшие приближения. Для игры про дронов и роботов это скорее плюс: набор будет звучать связно. Но исходный бриф «звук, который издаёт завод» выполнен приближённо, и если он важен буквально — нужен другой источник (Sonniss GDC Bundle, полевые записи).
- **Общего помещения не будет.** Реплики взяты из трёх разных паков, поэтому требование «одна импульсная характеристика на все файлы» невыполнимо, а `ConvolverNode` мы удаляем. Принимаем сухой звук: десять хвостов из десяти разных помещений звучали бы хуже.
- `select-tracks` и `explosion` по 0.777 с — длинновато для реплики выделения. Если гусеницы окажутся вязкими, обрезать до ~0.45 с фейдом (`-af "atrim=0:0.45,afade=t=out:st=0.44:d=0.01"`).
